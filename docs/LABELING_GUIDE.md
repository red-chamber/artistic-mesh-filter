# Labeling guide

## Current labels

当前初始标签是数据集代理标签：

- Toys4K：`label=1`；
- 自选 Objaverse：`label=0`。

这只能用于建立第一版基线。它无法排除数据来源、类别、格式、面数、尺度或转换工具造成的偏差。

## 负样本挑选标准

3000 个 Objaverse 负样本由一条独立的流水线筛出（参数已从它的 `status.json` 核实，见
`docs/DATA_CARD.md`）：

- 按种子 `20261014` 的顺序遍历 Objaverse 候选，逐个下载并用 Blender 导入；
- 接受条件：顶点数小于 20000、面数小于 20000、导入时是三角网格；
- 接受后用 Blender 的 OBJ 导出器重写一遍存盘；
- 质量不作要求：破碎几何、非必要的面数堆积、局部退化都在其中。这些正是负样本要体现的东西。

所以负标签是"套着筛选规则的代理标签"。配置里记作
`sources.objaverse.selection_rule`，上下界写在 `sources.objaverse.selection_limits`。
`smoke` 会用这两个界检查抽样资产，超出即判失败：如果一个未筛选的目录被误挂上来，标签的
含义就变了，必须在全量运行前发现。

两个必须记住的后果：

- "均为三角网格"这一条不要在本流水线里复核。trimesh 加载时就会三角化，四边形与多边形在
  加载后不可区分。上游 `manifest.csv` 的 `triangular` 字段才是权威记录——要复核就去读它，
  需要重新解析源文件时用 Assimp/Open3D。
- 面数上限是筛选标准的一部分，不是中性的观测。实测两个来源的面数分布大幅重叠
  （重叠带 [12, 15000]，Objaverse 92.8%、Toys4K 100% 落在带内），所以计数基线只拿到
  AUC 0.595，匹配面数后回到随机的 0.523。结论：面数有信息量但远不足以解释任务，
  `matched_test` 是判断任何模型是否真学到东西的必要口径。

还有一条更宽的捷径：负样本全部经 Blender 重导出，正样本是 Toys4K 原始文件，导出器指纹
本身就能区分两类。这条通道不影响当前的手工几何特征（它们只看几何），但会直接影响任何
读文件格式、材质或渲染图的模型。

## Human review labels

人工盲审时隐藏：

- 数据来源；
- 文件名和路径；
- 机器预测分数；
- 正负样本目录信息。

建议标签：

| Label | Meaning |
| --- | --- |
| `accept` | 拓扑整体符合 Artistic/Low-poly 使用目标 |
| `reject` | 明显扫描化、无意义密集、随机三角化或严重退化 |
| `uncertain` | 仅凭当前视图不能稳定判断 |
| `invalid` | 无法可靠显示或几何文件不可用，不参与 Artistic 好坏判断 |

### 盲审文件

`build-audit-gold` 输出两份表：

- `audit_gold.csv`：评审者使用的表，只有匿名编号、`asset_id` 和空的评审列。来源、路径、
  代理标签、面数都不在其中，因为知道面数会立刻把判断拉向"面少就是好"；
- `audit_gold_key.csv`：把匿名编号映射回来源与代理标签的对照表，只用于事后对账。

评审期间不要打开 key 表。这不是"尽量避免"的礼貌要求，而是唯一让盲审成立的条件：
表一旦被看过，后面的判断就没法当作独立证据。如果条件允许，让另一个人评审、你只看结果，
比你自己"假装不知道"更可信。

### 怎么看这些模型：直接看 3D，不渲染图片

`prepare-review` 把这张表变成评审者能直接打开的一批文件：

```bash
python -m mesh_filter prepare-review --config configs/paths.remote.yaml
```

它在 `outputs.review_dir` 下写出 `A0001.obj`、`A0002.obj`……和一个
`REVIEW_PROTOCOL.md`（操作说明）。用 VSCode 的 3D Viewer 打开即可：先开线框看边流与
面密度，再切实体看整体形状，允许自由旋转缩放。

不用渲染图片，理由有三条。判据本身是拓扑的——边流、面密度、细长三角形——这些在可旋转
的视图里比在几张固定视角图里更容易看清，固定视角会逼评审者去猜背面。渲染依赖 Blender
或 OpenGL，是这里最重的一环，省掉它就把整整一个后端选择推迟了。第三，`prepare-review`
会把每个模型居中并统一缩放到最长边为 1，所以尺度这条通道在视觉上直接消失——第一版忘了
做这一步，结果最长边在 12000 以上的几个模型在查看器里根本显示不全，已修。

重写成最简 OBJ 是匿名化的一步，不是格式化：负样本经 Blender 导出、正样本来自 Toys4K
原始发布，原始文件在顶点顺序、法线、UV 和数值格式上都带指纹，直接交原件等于把答案的一半
写在纸上。输出目录里只有 `v` 和 `f`，没有注释、没有材质、没有 UV、没有孤立顶点，两侧
从文件上完全看不出区别；所有文件共用同一个时间戳，文件日期也不会泄露来源。

局限也要说清楚：交互查看意味着每个评审者看到的信息量不完全一样，一致性不如固定图集，
所以要按 `REVIEW_PROTOCOL.md` 的固定顺序观察，并先看三个样本校准标准。另外，判断"外观
作为成品好不好看"、轮廓在简化后是否走形，这些确实需要渲染——第一轮盲审只问拓扑，不问
外观，所以不受影响。

## 判据（课题组给出）

Mesh 质量目前没有公认的定量指标。课题组给出的操作性判据有三条：

1. **面数与顶点数不能太大**；
2. **面的形状不能太规则**——接近等边三角形是坏的信号，不是好的信号；
3. **顶点的分布要整齐有规律**。

配图对比（线框截图）印证了三条的含义。较差的一批是扫描类玩偶与人像：表面被均匀密集的、
近似等边的小三角铺满，顶点看不出任何排布规律。较好的一批是耳机、风扇、人物模型：三角形
明显更细长、沿形状走向排列，耳机罩上有清晰的同心环，风扇的叶片与网罩结构一眼可见，平坦
处稀疏、转折处密集。

### 逐条落地成可计算的量

| 判据 | 代理量 | 期望方向 |
| --- | --- | --- |
| 面数/顶点数不能太大 | `face_count`、`vertex_count` | 低 = 好 |
| 面形状不能太规则 | `equilateral_ratio`（$q>0.9$ 的面占比） | **高 = 坏** |
| 面形状不能太规则 | `sliver_ratio`（$q<0.05$ 的面占比） | 单看无判别力，见下 |
| 顶点分布整齐 | `vertex_degree_mode_share`、`vertex_degree_entropy` | 集中 = 好 |
| 顶点分布整齐 | `one_ring_edge_length_cv_median` | 待实测 |
| 顶点分布整齐 | `local_edge_direction_anisotropy_mean` | 待实测 |
| 顶点分布整齐 | `neighboring_direction_consistency_mean` | 待实测 |
| 平坦处稀疏、转折处密集 | `curvature_density_correlation` | **正相关 = 好** |
| 多余的面 | `qem_redundancy_median` | 低 = 好 |

### 两个必须记住的点

**方向性纠偏。** 本项目早期文档把"接近等边三角形"写成几何上的理想状态，这是错的。等边度
高恰恰是自动重网格与扫描重建的典型特征——那类流程追求均匀采样。手工低模的三角形是细长
的、有方向的。这条纠偏改变若干特征的解读方向，已在 `docs/FEATURE_DEFINITIONS.md` 逐条标注。

**不要指望单一维度判别。** 细长面多本身不代表好，扫描网格里同样有细长面；等边度也不总是
满值。真正的区分是在（等边度，方向一致性）这个平面上：**等边 + 方向杂乱 = 扫描；细长 +
方向一致 = 手工**。单个特征只给出一个坐标，判据必须组合使用。

### 目标随之改变

原始设定是"用来源当标签的二分类"。盲审已经表明来源与人对质量的判断无关（决定性 161 行
一致 48.4%，Cohen kappa −0.03）。课题组给出的口径更直接：**写一个用这些几何量筛出好 mesh
的脚本**。Toys4K 里大部分是正例，可以用来估计筛选器的通过率；Objaverse 用来检验它能否从
一大堆普通网格里挑出少数好的。

评价口径也跟着变：不再是二分类 AUC，而是"筛出来的那批里好网格占多少"以及"在 Toys4K 上
通过多少"。`matched_test` 仍然是必要的对照——它保证通过率不是靠面数堆出来的。

### 人工评审时怎么用这三条

盲审时按同一个顺序看：先开线框，看三角形是不是普遍接近等边（若是，直接倾向 `reject`）；
再看顶点排布有没有规律（沿轮廓/环/边界成排，还是均匀铺满没有结构）；最后看平坦处是否
比转折处稀疏。只有前两条都过关、且找不到大面积冗余面的，才是 `accept`。
