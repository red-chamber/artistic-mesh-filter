# Labeling guide

## Current labels

当前初始标签是数据集代理标签：

- Toys4K：`label=1`；
- 自选 Objaverse：`label=0`。

这只能用于建立第一版基线。它无法排除数据来源、类别、格式、面数、尺度或转换工具造成的偏差。

## 负样本挑选标准

3000 个 Objaverse 负样本是提前人工筛过的，标准由用户于 2026-10-14 给出：

- 面数小于 20000，且顶点数小于 20000；
- 均为三角网格；
- 质量不作要求：破碎几何、非必要的面数堆积、局部退化都可以存在。这些正是负样本要
  体现的东西。

所以负标签是"套着筛选规则的代理标签"。配置里记作
`sources.objaverse.selection_rule = user_screened_triangle_meshes_under_20k_faces_and_vertices`，
上下界写在 `sources.objaverse.selection_limits`。`smoke` 会用这两个界检查抽样资产，超出
即判失败：如果一个未筛选的目录被误挂上来，标签的含义就变了，必须在全量运行前发现。

两个必须记住的后果：

- "均为三角网格"这一条本流水线无法复核。trimesh 在加载时就三角化，四边形与多边形在加载后
  不可区分（见 `docs/REMOTE_WORKFLOW.md` 的已知限制）。要复核必须另用 Assimp/Open3D 做
  原始解析，因此这一条只能作为对数据集的声明，不能当作可验证的不变量。
- 面数上限是筛选标准的一部分，不是中性的观测。如果 Toys4K 正样本的面数分布与"小于
  20000"的负样本几乎不重叠，那么只用面数/顶点数的计数基线会得到很高的分数，而这个分数
  来自筛选规则而非拓扑质量。真实数据到手后第一件该看的事就是两个来源的面数分布；只要
  它们分开，`matched_test` 面数匹配测试集就不是可选项，而是解释任何结果的前提。

## Human review labels

人工盲审时隐藏：

- 数据来源；
- 文件名和路径；
- 机器预测分数；
- 正负样本目录信息。

建议标签：

| Label | Meaning |
| --- | --- |
| `accept` | 拓扑整体符合 Artistic/Low-poly 使用目标 |
| `reject` | 明显扫描化、无意义密集、随机三角化或严重退化 |
| `uncertain` | 仅凭当前视图不能稳定判断 |
| `invalid` | 无法可靠显示或几何文件不可用，不参与 Artistic 好坏判断 |

### 盲审文件

`build-audit-gold` 输出两份表：

- `audit_gold.csv`：评审者使用的表，只有匿名编号、`asset_id` 和空的评审列。来源、路径、
  代理标签、面数都不在其中，因为知道面数会立刻把判断拉向"面少就是好"；
- `audit_gold_key.csv`：把匿名编号映射回来源与代理标签的对照表，只用于事后对账。

评审期间不要打开 key 表。这不是"尽量避免"的礼貌要求，而是唯一让盲审成立的条件：
表一旦被看过，后面的判断就没法当作独立证据。如果条件允许，让另一个人评审、你只看结果，
比你自己"假装不知道"更可信。

### 盲审还缺图片

`audit_gold.csv` 只给出样本和分层，评审者要看的图依赖渲染环节，而渲染尚未实现（见
`docs/OPEN_QUESTIONS.md`）。在渲染后端确定之前，这张表只能先建好、不能真用。

## Review criteria

重点观察：

- 平坦区域是否保持稀疏；
- 折痕、轮廓和零件边界是否获得必要边；
- 局部边流是否连续、有结构；
- 是否存在大量接近等边的小三角形；
- 是否存在大量细长、退化三角形；
- 多边形是否用于表达形状，而非无意义堆积。

人工审计集应包含高分、低分、边界样本，以及匹配面数和类别的正负样本。
